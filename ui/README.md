# LexCheck frontend

React frontend adapted from the user-supplied `lexcheck-ui` HTML/CSS/JavaScript prototype. Only the integrated source and required assets are included in this PR; the original prototype and proposal remain local. The app reuses its green/cream palette, sidebar, mascot and evidence panel, with Nunito Sans replacing the original sans/serif mix.

## Run on Windows

Requires Node 22.12+ and the repository's Python 3.11 environment.

```powershell
cd ui
npm ci
npm run build
cd ..
.venv/Scripts/python.exe -X utf8 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000. FastAPI already mounts `ui/dist`; no backend or contract changes are needed. `-X utf8` is necessary on Windows because existing Python file readers use the system default encoding.

For development run the API as above, then `cd ui; npm run dev` in another terminal. Vite proxies `/api` and `/health` to port 8000.

## Checks

```powershell
cd ui
npm test -- --run
npm run build
npm run test:e2e
```

Start the API on port 8000 before E2E. The suite starts Vite itself. Install bundled Chromium with `npx playwright install chromium`; set `PW_CHANNEL=msedge` only when explicitly testing Edge. The suite checks real fixture API reads/checks and unavailable writes, explicitly labelled UI-only finding/account-switch responses, offline fallback, and layouts at 1280×720, 768×1024 and 375×812.

From the repository root: `.venv/Scripts/python.exe -X utf8 -m pytest -q --cov` and `.venv/Scripts/python.exe -X utf8 -m eval.run`.

## API and limits

- Loads `/api/demo` and `/api/history`; sends checks, reviewer decisions, change events and recheck requests using the existing contracts.
- API errors remain visible. A 503 never becomes a successful write in local state. Zero executed rules never becomes a clean result.
- Current engine is a fixture adapter: all eight catalog rules remain disabled; decisions, changes and rechecks return 503. Main now supplies detection, validator and cited chat modules, but the real engine/impact integration remains pending. Frontend controls are wired for these APIs, but their presence does not establish a completed live flow.
- The chat shell is accessible from “Trợ lý Lex”, “Cuộc trò chuyện mới” or `/#chat`, while Review remains the landing view. Until `/api/features` enables layer 1, it shows “Chưa kết nối chatbot” and disables questions without calling the chat API. Once enabled, it calls `/api/chat` on a selected check and displays only the returned citations/status. Scripted answers have been removed.
- `/demo.json` is generated by Vite from the current fixture on every build/dev request. Only shared demo records are bundled; manager-only records are excluded using the server access fixture. It is labelled `synthetic/staged` and fixture/offline, blocks writes, and is not an evaluation result or a model cache. A history HTTP failure retains the API dossier and shows its own error.
- Source evidence is rendered as text by React. Span highlighting requires exact original offsets/quote; Python code-point offsets and original text are preserved without changing normalization under the offsets.
- Review, Evidence, History, Chat, Sources, Updates and the later-layer panels are separate components. New versions, closure, legal interpretation, evaluation and feedback controls use the existing contracts and remain subject to backend gates. Their presence is not a claim of completed engine integration.
- Local WOFF2 assets include Vietnamese glyphs. There is no runtime Google Fonts request.
